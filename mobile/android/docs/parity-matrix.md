# Native Android Full Parity Matrix

Baseline source: static scan of `web/src/App.tsx`, `web/src/pages`, `web/src/components`, `web/src/api`, `web/src/stores`, and `web/src/sw` on 2026-06-08.

Status values: `not-started`, `backend-gap`, `design-ready`, `in-progress`, `test-ready`, `complete`, `intentionally-excluded`.

Completion rule: a row can be `complete` only after the native Android flow is implemented without WebView, verified against web behavior, covered by appropriate tests or evidence, and includes loading, empty, success, error, offline, retry, and permission states where applicable.

## Cross-Cutting Workflow Rows

| Workflow | Status | Required native parity |
| --- | --- | --- |
| Auth guard and 401 handling | complete | Native guards protected routes, attaches bearer tokens, and attempts refresh-token recovery through `POST /v1/auth/sessions:refresh` before logout fallback. |
| Native Google sign-in | backend-gap | Web uses Google Identity in browser and `POST /v1/auth/google`; Android needs native OAuth client and backend exchange confirmation. |
| Refresh-token auth | complete | Backend now returns refresh tokens on login and exposes token rotation through `POST /v1/auth/sessions:refresh`; Android uses single-flight refresh for normal requests and offline sync. |
| Command palette and shell actions | complete | Native provides quick-navigation sheet search, top-app-bar actions, and route-level navigation affordances as the Android equivalent of the web command palette and shell actions. |
| Desktop/mobile shell adaptation | complete | Native uses platform-appropriate top app bar, bottom navigation, and route sheet behavior instead of reproducing the web desktop/mobile shell split verbatim. |
| Offline progress sync | complete | Android now uses Room-backed caches, DataStore preferences, encrypted token storage, feature-scoped idempotent sync events, WorkManager processing, conflict/failed-state handling, and visible retry banners across lessons, flashcards, focus, goals, and settings. Verified by `OfflineSyncTest`, `AppDatabaseMigrationTest`, and device-executed lesson/flashcard instrumentation coverage on `codex_api36`. |
| Lesson block rendering | complete | Native supports typed blocks, segmented lessons, inline checks, practice, and tutor panels. Mapper unit tests pass, and device-executed instrumentation covers tables, code, formulas, callouts, checks, segment navigation, completion, and cached offline reading. |
| Analytics chart accessibility | complete | Native analytics and readiness use accessible summary text, labeled progress bars, selected-point details, and empty/error states instead of opaque visuals. |
| Admin role gating | complete | Native admin screen has defense-in-depth role gating: nav-level filtering via `adminOnly = true` on the shell destination, plus a screen-level role check inside `AdminDashboardScreen` that renders a locked state for non-admin accounts. |
