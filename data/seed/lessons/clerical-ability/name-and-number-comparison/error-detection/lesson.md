# Error Detection

## Explanations

### Introduction

Error detection is a clerical checking skill that requires examinees to identify discrepancies between two or more versions of the same record — which may contain names, numbers, alphanumeric codes, or a combination of all three. In the Philippine Civil Service Examination (CSE) Sub-Professional level, this skill falls under clerical operations and represents the most comprehensive form of comparison testing: rather than comparing a single data type in isolation, the examinee must scan an entire record entry and pinpoint exactly where — and what type of — error has been introduced.

Government clerks encounter error detection tasks constantly: verifying that a typed payroll entry matches the handwritten source document, confirming that a disbursement voucher's payee name, amount, and reference code all match the corresponding obligation request, and checking that an employee's CS Form 212 data was correctly encoded into the Human Resource Information System. A single undetected error — a transposed digit in an account number, a missing letter in a surname, or a wrong separator in a document code — can cause misdirected payments, misfiled records, or audit exceptions that require hours of investigation to resolve.

Error detection questions on the CSE present a source record and one or more transcribed versions, then ask the examinee to identify which version contains an error, what type of error it is, or how many errors are present. The skill synthesizes name comparison, number comparison, and alphanumeric comparison into a single, time-pressured task — making it the highest-difficulty item type in the clerical section.

### Why Error Detection Is Tested in the CSE

- Government clerks routinely verify data transcribed from source documents into official records, databases, and forms.
- A single undetected error in a government record can cause financial loss, delayed services, or legal complications.
- Error detection tests the ability to apply multiple comparison rules simultaneously — a core competency for data entry and records management positions.
- The skill measures sustained attention: errors are deliberately placed in unexpected positions to catch examinees who scan selectively.
- Philippine government records combine names, codes, dates, and amounts in a single entry — clerks must check all components, not just one.
- Detecting errors before they propagate through a system is far cheaper than correcting them after the fact.
- The CSE uses error detection to distinguish examinees who can maintain accuracy under time pressure from those who can only check slowly.

### Common Mistakes Examinees Make

1. Checking only the most prominent field (usually the name) and ignoring numbers and codes.
2. Stopping after finding the first error instead of verifying whether the question asks for all errors.
3. Confusing visually similar characters across data types: O/0, I/1, S/5, Z/2, rn/m.
4. Overlooking punctuation and spacing differences (periods, commas, hyphens, spaces) as "not real errors."
5. Reading records holistically instead of field by field, component by component.
6. Assuming that if the name is correct, the rest of the record must be correct too.
7. Misidentifying the error type — calling a transposition a substitution, or an omission an addition.
8. Rushing through familiar-looking data (common surnames, standard codes) without actually comparing each character.

### Learning Objectives

By the end of this lesson, you should be able to:

- Identify errors in records containing names, numbers, alphanumeric codes, and mixed data.
- Classify detected errors as substitution, transposition, omission, or addition.
- Apply a systematic field-by-field comparison strategy to multi-component records.
- Recognize the visual traps most commonly used in CSE error detection questions.
- Determine whether two records are identical or contain one or more discrepancies.
- Maintain accuracy while working under time pressure on complex, multi-field records.
- Distinguish between errors in the name portion, number portion, and code portion of a record.
- Count the total number of errors in a record when the question requires it.

### 4.1 What Error Detection Tests

Error detection is the synthesis of all comparison skills. It tests one overarching question: **can you find every discrepancy between a source record and a transcribed version, across all data fields, under time pressure?**

Unlike name comparison (which tests only names) or number comparison (which tests only numbers), error detection presents complete records — the kind a government clerk would actually verify. A record might contain a surname, a first name, an employee ID, a salary grade, a date, and a budget code. Any of these fields can contain an error. The examinee must check all of them.

**The four error types apply across all data fields:**

| Type | In Names | In Numbers | In Codes |
|------|----------|-----------|---------|
| Substitution | Gonzale**s** → Gonzale**z** | 482**7** → 482**9** | CSC-R**3**-045 → CSC-R**4**-045 |
| Transposition | Re**ye**s → Re**ey**s | 48**27** → 48**72** | DV-2024-0**14**2 → DV-2024-0**41**2 |
| Omission | Vi**ll**anueva → Vi**l**anueva | 2024-0**0**1 → 2024-**0**1 | OSEC-0**0**001 → OSEC-**0**001 |
| Addition | Cruz → Cru**i**z | 4827 → 48**2**27 | PS-101-001 → PS-101-0**0**01 |

> 🤔 **Why does this work?** Error detection works as a synthesis task because real government records are multi-field documents. A payroll entry is not just a name — it is a name, an ID number, a salary grade, a period, and an amount. Training yourself to check each field independently, using the appropriate comparison strategy for that field type, mirrors exactly what a competent government clerk does when verifying records. The skill is not harder in principle — it is harder in practice because it requires sustained attention across more data than a single-field comparison.

### 4.2 The Four-Field Record Structure

Most CSE error detection questions use records with two to five fields. Understanding the standard field types helps you know what comparison strategy to apply to each.

**Field types and their comparison rules:**

| Field Type | Examples | Comparison Rule |
|-----------|---------|----------------|
| Name field | SANTOS, JUAN PEDRO | Character-by-character; check particles, punctuation, suffixes |
| Number field | 09171234567, ₱12,345.67 | Digit-by-digit; check separators, leading zeros, decimal places |
| Code field | CSC-2024-03-0042 | Segment-by-segment; check separators, leading zeros, ambiguous chars |
| Date field | 03/15/2024, 15-Mar-2024 | Year → Month → Day; check format, leading zeros, separator type |
| Amount field | ₱1,234,567.89 | Digit-by-digit; check peso sign, commas, decimal, trailing zeros |

**Standard government record format:**

```
[SURNAME, FIRST NAME M.I.]  [EMPLOYEE ID]  [SALARY GRADE]  [DATE]
```

Example:
```
REYES, MARIA TERESA C.    EMP-2024-00246    SG-15-4    03/15/2024
```

> 🤔 **Why does this work?** Knowing the standard field structure lets you divide a complex record into predictable components before you start comparing. Instead of facing a 50-character string, you face four 10-12 character segments — each with its own comparison rule. This divide-and-conquer approach keeps each sub-task within working memory capacity and prevents the cognitive overload that causes errors to slip through.

### 4.3 The Systematic Error Detection Method

Apply this five-step method to every error detection question:

**Step 1: Count the fields.**
Identify how many distinct data fields the record contains. This tells you how many separate comparisons you need to make.

**Step 2: Check field count and total length.**
If the transcribed version has a different number of fields, or a field is visibly shorter or longer, you have already found an omission or addition error.

**Step 3: Compare field by field, left to right.**
Apply the appropriate comparison rule to each field:
- Name fields: character by character, checking particles, punctuation, and suffixes.
- Number/amount fields: digit by digit, checking separators and leading zeros.
- Code fields: segment by segment, checking separators, leading zeros, and ambiguous characters.
- Date fields: year, then month, then day; check format and leading zeros.

**Step 4: Flag ambiguous characters.**
When you encounter O/0, I/1, l/1, S/5, Z/2, B/8, or G/6 in any field — slow down and verify explicitly.

**Step 5: Report your finding.**
- If the question asks "are they identical?" — answer Yes or No.
- If the question asks "what type of error?" — name the type (substitution, transposition, omission, addition).
- If the question asks "how many errors?" — count all discrepancies across all fields.
- If the question asks "which version is correct?" — identify the version that matches the source.

> ⚠️ **Misconception:** "If I find one error, I can stop checking."
>
> **Why it fails:** Some CSE questions ask "how many errors are present?" or "which of the following contains TWO errors?" If you stop at the first error, you will miss the second and answer incorrectly. Always read the question stem carefully to know whether you need to find one error or all errors.
>
> **Correct model:** Read the question first. If it asks for the number of errors or asks you to identify all errors, you must check every field completely — even after finding the first discrepancy.

### 4.4 Error Location Patterns

Errors in CSE questions are not placed randomly. Understanding where errors are most commonly hidden helps you allocate your attention efficiently.

**High-frequency error locations:**

| Location | Why It's a Trap |
|----------|----------------|
| Middle of a long surname | Brain reads the beginning and end, skips the middle |
| Last digit of a number sequence | Transpositions at the end are easy to miss |
| Leading zeros in code segments | Zeros are visually "empty" — easy to overlook |
| Name particles (Dela, De La, Delos) | Spacing differences look like formatting, not errors |
| Suffix punctuation (Jr., Sr.) | Period presence/absence seems trivial |
| Ambiguous characters (O/0, I/1) | Look identical in most printed fonts |
| Second-to-last segment of a code | Attention fades before reaching the end |
| Centavo digits in financial amounts | Small values feel less important |

**The "middle trap" in names:**

```
Source:      VILLANUEVA, ROBERTO ENRIQUEZ
Transcribed: VILLANUEVA, ROBERTO ENRIQUES
                                       ↑
                              z → s (substitution, near the end)
```

**The "leading zero trap" in codes:**

```
Source:      OSEC-00001-001
Transcribed: OSEC-0001-001
                  ↑
         One zero omitted (omission)
```

> ⚠️ **Misconception:** "Errors are always in the most complex-looking part of the record."
>
> **Why it fails:** CSE question writers deliberately place errors in simple-looking positions — a single digit at the end of a code, a period after "Jr," a space in "De La Cruz" — precisely because examinees assume complex sections are where errors hide. The simplest-looking field is often where the trap is set.
>
> **Correct model:** Check every field with equal thoroughness. Do not spend extra time on complex fields at the expense of simple ones. The error is equally likely to be in the last digit of a sequence number as in the middle of a long surname.

### 4.5 Error Types in Detail

#### Substitution

One character is replaced by a different character. The total length of the field is unchanged.

**In names:**
- GONZALE**S** → GONZALE**Z** (s replaced by z)
- HERNANDE**Z** → HERNANDE**S** (z replaced by s)
- VILLA**N**UEVA → VILLA**M**UEVA (n replaced by m — rn/m visual trap)

**In numbers:**
- 482**7** → 482**9** (7 replaced by 9)
- ₱12,3**4**5.67 → ₱12,3**5**5.67 (4 replaced by 5)

**In codes:**
- CSC-R**3**-045 → CSC-R**4**-045 (3 replaced by 4)
- COA-R3-**0**45 → COA-R3-**O**45 (digit 0 replaced by letter O)

**Detection tip:** Substitutions do not change field length. If both versions look the same length but differ, look for a substitution.

#### Transposition

Two adjacent characters are swapped. The total length of the field is unchanged.

**In names:**
- RE**YE**S → RE**EY**S (y and e swapped)
- BAUTIS**TA** → BAUTIS**AT** (t and a swapped)

**In numbers:**
- 48**27** → 48**72** (2 and 7 swapped)
- 2024-0**14**2 → 2024-0**41**2 (1 and 4 swapped)

**In codes:**
- DI**LG**-2024-001 → DI**GL**-2024-001 (L and G swapped)
- PS-101-20**24**-001 → PS-101-20**42**-001 (2 and 4 swapped)

**Detection tip:** Transpositions are the hardest to catch because both versions look like valid data. Force yourself to compare position by position — do not read the field as a whole.

#### Omission

One character is missing. The transcribed version is one character shorter than the source.

**In names:**
- VI**LL**ANUEVA → VI**L**ANUEVA (one L omitted)
- PANGILI**N**AN → PANGILI**_**AN (n omitted)

**In numbers:**
- 2024-0**0**1 → 2024-**0**1 (leading zero omitted)
- ₱1**0**0,000.00 → ₱1**_**0,000.00 (zero omitted — factor of 10 error)

**In codes:**
- OSEC-0**0**001-001 → OSEC-**0**001-001 (leading zero omitted)
- CSC-2024-**0**3-0042 → CSC-2024-**_**3-0042 (leading zero omitted)

**Detection tip:** A length check catches omissions immediately. If the transcribed version is shorter, a character was dropped.

#### Addition

An extra character is inserted. The transcribed version is one character longer than the source.

**In names:**
- CRUZ → CRU**I**Z (extra i inserted)
- MANALO → MANA**L**LO (extra l inserted)

**In numbers:**
- 4827 → 48**2**27 (extra 2 inserted)
- 2024-001 → 2024-0**0**01 (extra leading zero inserted)

**In codes:**
- PS-101-001 → PS-101-0**0**01 (extra leading zero inserted)
- COA-R3-045 → COA-R**3**3-045 (extra 3 inserted)

**Detection tip:** A length check catches additions immediately. If the transcribed version is longer, a character was inserted.

> 🤔 **Why does this work?** Classifying errors by type works because each type has a distinct signature: substitutions preserve length, transpositions preserve length and character set, omissions shorten the field, additions lengthen it. By checking length first, you immediately narrow the error type to either substitution/transposition (same length) or omission/addition (different length). This halves the number of possibilities before you even start comparing characters.

### 4.6 Multi-Field Records: The Full Verification Workflow

When a record contains multiple fields, apply the systematic method to each field in sequence. Do not skip fields because they "look right."

**Example record:**

```
Source:      DELA CRUZ, JUAN PEDRO R.    EMP-2024-00246    SG-15-4    03/15/2024
Transcribed: DELA CRUZ, JUAN PEDRO R.    EMP-2024-00264    SG-15-4    03/15/2024
```

**Field-by-field verification:**

| Field | Source | Transcribed | Match? |

| Name | DELA CRUZ, JUAN PEDRO R. | DELA CRUZ, JUAN PEDRO R. | ✓ |
| Employee ID | EMP-2024-00246 | EMP-2024-00264 | ✗ (246 → 264, transposition) |
| Salary Grade | SG-15-4 | SG-15-4 | ✓ |

**Result:** NOT identical — transposition in the employee ID (last segment: 00246 → 00264).

### 4.7 Counting Errors: When the Question Asks "How Many?"

Some CSE questions present a record with multiple errors and ask how many discrepancies exist. This requires a complete check of every field — you cannot stop at the first error.

**Strategy for counting errors:**

1. Check every field completely, even after finding the first error.
2. Keep a running tally: mark each discrepancy as you find it.
3. Do not count the same error twice (e.g., a transposition is one error, not two substitutions).
4. Report the total count.

**Example:**

```
Source:      SANTOS, MARIA TERESA V.    EMP-2024-00135    SG-11-2    04/30/2024
Transcribed: SANTSO, MARIA TERESA V.    EMP-2024-00135    SG-11-2    04/30/2024
```

| Field | Error? | Type |
|-------|--------|------|
| Name | SANTOS → SANTSO | Transposition (O and S swapped) |
| Employee ID | EMP-2024-00135 = EMP-2024-00135 | None |
| Salary Grade | SG-11-2 = SG-11-2 | None |
| Date | 04/30/2024 = 04/30/2024 | None |

**Total errors: 1** (transposition in surname)

**Example with two errors:**

```
Source:      REYES, PEDRO ANTONIO M.    EMP-2024-00312    SG-18-6    01/15/2025
Transcribed: REYES, PEDRO ANTONIO M.    EMP-2024-00312    SG-18-6    01/51/2025
```

| Field | Error? | Type |
|-------|--------|------|
| Name | Match | None |
| Employee ID | Match | None |
| Salary Grade | Match | None |
| Date | 01/15/2024 → 01/51/2024 | Transposition (1 and 5 in day) |

Wait — source year is 2025, transcribed year is 2025. Day: 15 → 51. **Total errors: 1** (transposition in day portion of date).

> 🤔 **Why does this work?** Counting errors requires a complete scan because question writers sometimes place a second error in a field you already checked — or in the last field, knowing that examinees who found the first error will stop early. A complete field-by-field scan, regardless of what you have already found, is the only reliable way to get the count right.

### 4.8 Visual Traps Specific to Error Detection

Error detection questions combine the visual traps from all three comparison subtopics. The following are the most dangerous combinations:

#### Cross-Field Ambiguity

A character that is correct in one field type may be wrong in another. For example:
- "O" is a valid letter in a name (SANTOS) but may be a mistyped "0" in a code (COA-R3-O45).
- "1" is a valid digit in a number but may be a mistyped "I" in a code (ID-1234 vs. ID-I234).

When a record contains both names and codes, you must apply the correct interpretation to each field independently.

#### The "Correct Name, Wrong Code" Trap

The most common error detection trap: the name field is correct, but the code or number field contains the error. Examinees who check the name first and find it correct often relax their attention for the remaining fields.

```
Source:      VILLANUEVA, ROBERTO C.    EMP-2024-00135    SG-15-4
Transcribed: VILLANUEVA, ROBERTO C.    EMP-2024-00153    SG-15-4
                                                  ↑
                                    Transposition: 135 → 153
```

#### The "Correct Code, Wrong Name" Trap

The reverse: the code is correct, but the name contains the error.

```
Source:      HERNANDEZ, JOSE ANTONIO    CSC-2024-03-0042    SG-22-8
Transcribed: HEMANDEZ, JOSE ANTONIO     CSC-2024-03-0042    SG-22-8
                  ↑
         rn → m substitution (visual trap)
```

#### The "Last Field" Trap

The error is placed in the last field of the record, where attention is lowest.

```
Source:      GARCIA, ELENA REYES    EMP-2024-00089    SG-9-3    03/15/2024
Transcribed: GARCIA, ELENA REYES    EMP-2024-00089    SG-9-3    03/51/2024
                                                                      ↑
                                                         Transposition in day: 15 → 51
```

### 4.9 Philippine Government Record Formats

Understanding the standard formats used in Philippine government records helps you recognize what each field should look like — and spot deviations faster.

**Employee record entry (CS Form 212 / HRIS):**

| Field | Format | Example |
|-------|--------|---------|
| Name | SURNAME, FIRST NAME M.I. | DELA CRUZ, JUAN PEDRO R. |
| Employee ID | EMP-YYYY-NNNNN | EMP-2024-00246 |
| Salary Grade | SG-NN-N | SG-15-4 |
| Date | MM/DD/YYYY | 03/15/2024 |
| Position code | XXXX-NNNNN-NNN | OSEC-00001-001 |

**Disbursement voucher entry:**

| Field | Format | Example |
|-------|--------|---------|
| Payee name | SURNAME, FIRST NAME M.I. | SANTOS, MARIA TERESA C. |
| DV number | DV-YYYY-MM-NNNN | DV-2024-03-0042 |
| Amount | ₱N,NNN,NNN.NN | ₱12,345.67 |
| Budget code | XX-NNN | PS-101 |
| Date | MM/DD/YYYY | 04/30/2024 |

**Payroll register entry:**

| Field | Format | Example |
|-------|--------|---------|
| Employee name | SURNAME, FIRST NAME M.I. | REYES, PEDRO ANTONIO M. |
| Employee ID | NNN-NNNNNNN-N (SSS) | 34-1234567-8 |
| Gross pay | ₱N,NNN.NN | ₱18,549.00 |
| Net pay | ₱N,NNN.NN | ₱15,230.50 |
| Period | MM/DD/YYYY – MM/DD/YYYY | 03/01/2024 – 03/15/2024 |

> 🤔 **Why does this work?** Knowing the expected format for each field type gives you a template to compare against. When you see "SG-15-4" in a salary grade field, you know it should be two digits after "SG-" and one digit after the second hyphen. If you see "SG-1-54," you immediately know the format is wrong — even before doing a character-by-character comparison. Format knowledge is a fast pre-check that catches structural errors before you invest time in detailed comparison.

### 4.10 Speed vs. Accuracy Tradeoff

The CSE is time-pressured: 165 items in 2 hours 40 minutes (approximately 58 seconds per item). Error detection items are the most complex in the clerical section and should take 30-50 seconds each. Here's how to manage the tradeoff:

**Speed techniques that maintain accuracy:**

1. **Field count first:** Count the number of fields in both records. Different counts = instant "not identical."
2. **Length scan:** Quickly estimate the length of each field. A visibly shorter or longer field signals omission or addition.
3. **Name field first:** Start with the name — it is usually the longest field and the most likely to contain a trap.
4. **Code field last:** Codes are shorter and more structured; save them for last when your attention is still adequate.
5. **Ambiguous character flag:** When you see O, 0, I, 1, S, 5, Z, 2 — slow down for that position only.
6. **Stop when the question allows:** If the question asks only "are they identical?" — stop at the first error. If it asks "how many errors?" — check everything.

**Time allocation per field type:**

| Field Type | Target Time |
|-----------|------------|
| Short name (surname only) | 5-8 seconds |
| Full name (surname + first + MI) | 10-15 seconds |
| Employee ID / document code | 8-12 seconds |
| Financial amount | 8-10 seconds |
| Date | 5-8 seconds |
| Salary grade | 3-5 seconds |

**Total for a 4-field record:** approximately 30-45 seconds — within the 58-second budget.

### 4.11 CSE Question Formats for Error Detection

**Format 1: Are the records identical?**
```
Directions: Compare the two records. Mark A if they are EXACTLY alike,
mark B if they are NOT exactly alike.

Source:      SANTOS, JUAN PEDRO R.    EMP-2024-00135    SG-15-4
Transcribed: SANTOS, JUAN PEDRO R.    EMP-2024-00135    SG-15-4
```

**Format 2: Identify the error**
```
Directions: The transcribed record contains ONE error. What type of error is it?

Source:      REYES, MARIA TERESA C.    EMP-2024-00246    SG-11-2
Transcribed: REYES, MARIA TERESA C.    EMP-2024-00264    SG-11-2

A. Substitution in the name field
B. Transposition in the employee ID
C. Omission in the salary grade
D. Addition in the employee ID
```

**Format 3: How many errors?**
```
Directions: How many errors does the transcribed record contain?

Source:      VILLANUEVA, ROBERTO C.    EMP-2024-00135    SG-15-4    03/15/2024
Transcribed: VILANUEVA, ROBERTO C.     EMP-2024-00135    SG-15-4    03/51/2024

A. 0    B. 1    C. 2    D. 3
```

**Format 4: Which version is correct?**
```
Directions: The source record is: DELA CRUZ, JUAN PEDRO R.    EMP-2024-00246    SG-15-4
Which of the following transcribed versions is EXACTLY correct?

A. DELA CRUZ, JUAN PEDRO R.    EMP-2024-00264    SG-15-4
B. DE LA CRUZ, JUAN PEDRO R.   EMP-2024-00246    SG-15-4
C. DELA CRUZ, JUAN PEDRO R.    EMP-2024-00246    SG-15-4
D. DELA CRUZ, JUAN PEDRO R.    EMP-2024-00246    SG-51-4
```

**Format 5: Find the error location**
```
Directions: In which field does the error appear?

Source:      HERNANDEZ, JOSE A.    CSC-2024-03-0042    SG-22-8    01/15/2025
Transcribed: HEMANDEZ, JOSE A.     CSC-2024-03-0042    SG-22-8    01/15/2025

A. Name field    B. Document code    C. Salary grade    D. Date field
```

### Check Your Understanding

**1.** A source record reads "GONZALES, PEDRO" and the transcribed version reads "GONZALEZ, PEDRO." What type of error is this? → **Substitution** (s → z in surname)

**2.** A source code reads "EMP-2024-00135" and the transcribed version reads "EMP-2024-00153." What type of error is this? → **Transposition** (3 and 5 swapped in last segment)

**3.** A source record reads "VILLANUEVA, ROBERTO C." and the transcribed version reads "VILANUEVA, ROBERTO C." What type of error is this? → **Omission** (one L dropped from surname)

**4.** A source record has 4 fields. The transcribed version has 4 fields. Does this guarantee they are identical? → **No** — same field count only rules out structural omission/addition; substitution and transposition errors are still possible within fields.

**5.** A question asks "how many errors are present?" You find an error in the name field. Should you stop checking? → **No** — you must check all remaining fields to give an accurate count.

### Exam Strategies

- Read the question stem before looking at the records. Know whether you need to find one error, count all errors, or identify the error type — this determines how thoroughly you must check.
- Always start with a field count and length scan. These two quick checks catch omission and addition errors in seconds.
- Compare the name field first — it is usually the longest and most error-prone.
- For codes and numbers, use separators as natural breakpoints and compare segment by segment.
- When you see O, 0, I, 1, S, 5, Z, or 2 in any field — slow down for that position only, then resume normal speed.
- For "which version is correct?" questions, use elimination: find the error in each option until you find the one with no error.
- Do not assume the error is in the most complex-looking field. Check every field.
- On the CSE, you have roughly 1 minute per item. Allocate 30-45 seconds for a 4-field record — leave 10-15 seconds to verify your answer.
- Trust your systematic method. If your field-by-field comparison finds no difference, the records are identical — do not second-guess yourself.
- For "how many errors?" questions, keep a running tally as you check each field. Do not try to hold the count in memory — mark it on your scratch paper.

### Memory Aids

#### The FLEET Method for Error Detection

**F** — Fields: Count the fields in both records first
**L** — Length: Check each field's length before comparing characters
**E** — Each field: Compare every field, left to right, using the right rule
**E** — Error type: Classify each discrepancy (substitution, transposition, omission, addition)
**T** — Tally: Count total errors if the question requires it

#### The "STOP Before You Skip" Rule

Before moving from one field to the next, ask yourself: "Did I actually compare every character in this field, or did I just glance at it?" If you glanced, go back. The error is most likely in the field you almost skipped.

#### Error Type Quick Reference

| Clue | Error Type |
|------|-----------|
| Same length, one character different | Substitution |
| Same length, two adjacent characters swapped | Transposition |
| Transcribed version is shorter | Omission |
| Transcribed version is longer | Addition |

#### The "Last Field" Reminder

Always check the last field. Question writers know that attention fades toward the end of a record. The last field — whether it is a date, a salary grade, or a sequence number — is a favorite location for the trap.

## Key Takeaways

- Error detection synthesizes name comparison, number comparison, and alphanumeric comparison into a single multi-field task.
- The four error types — substitution, transposition, omission, addition — apply to every field type: names, numbers, codes, and dates.
- Always read the question stem first: know whether you need to find one error, count all errors, or identify the error type before you start comparing.
- Apply a field-by-field strategy: count fields, check lengths, then compare each field using the appropriate rule for that data type.
- Length differences between fields immediately identify omission (shorter) or addition (longer) errors — no character comparison needed.
- Same-length fields with discrepancies contain substitution or transposition errors.
- The eight ambiguous characters (O/0, I/1, l/1, S/5, Z/2, B/8, G/6) are the most dangerous positions in any field — slow down when you encounter them.
- Common error location traps: last field of the record, middle of a long surname, leading zeros in code segments, name particles, suffix punctuation.
- Do not stop checking after finding the first error when the question asks for a count — check every field completely.
- The FLEET method (Fields, Length, Each field, Error type, Tally) provides a reliable, repeatable workflow for any error detection question.

## Summary

Error detection is the most comprehensive clerical checking skill tested on the Philippine Civil Service Examination Sub-Professional level. It requires examinees to compare multi-field records — containing names, employee IDs, document codes, financial amounts, and dates — and identify any discrepancy between a source document and a transcribed version. The skill directly mirrors what government clerks do when verifying payroll entries, disbursement vouchers, and personnel records in daily operations.

The four error types — substitution (one character replaced), transposition (two adjacent characters swapped), omission (a character missing), and addition (an extra character inserted) — apply uniformly across all field types. A systematic field-by-field approach, using the appropriate comparison rule for each data type, is the only reliable method for catching errors under time pressure. Length checks provide a fast first screen: fields of different lengths immediately signal omission or addition errors, while same-length fields with discrepancies contain substitution or transposition errors.

Success in error detection requires sustained attention across the entire record, not just the most prominent field. Question writers deliberately place errors in unexpected locations — the last field, a leading zero, a suffix period, an ambiguous O/0 character — to catch examinees who check selectively. The FLEET method (Fields, Length, Each field, Error type, Tally) provides a structured workflow that ensures complete coverage of every field within the time budget of approximately 30-45 seconds per record. Mastery of this skill, combined with the name comparison, number comparison, and alphanumeric comparison techniques it builds upon, prepares examinees for the full range of clerical checking tasks on the CSE.
